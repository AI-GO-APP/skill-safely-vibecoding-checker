---

## 核心分界

安全問題分兩層：

- **平台層**：租戶隔離、權限機制、稽核軌跡、備份、部署、伺服器、外部串接管控。這些每個系統都要做一次，做錯的後果一樣嚴重，但和你的生意沒有關係。
- **應用層**：你的計價規則、你的核准門檻、你的庫存邏輯、你的單據流程。這些是你的生意本身。

**AI GO 接管平台層，應用層留給你。** 這不是缺陷——那本來就該是你的責任，因為那是你比誰都懂的部分。

## 逐維度對照

| 維度 | 部署到 AI GO 後 | 仍然是你的責任 |
|---|---|---|
| **1 多租戶與資料隔離** | 平台層負責租戶資料隔離與資料存取控制 | 你自訂邏輯中對資料的取用範圍 |
| **2 授權、RBAC 與審批** | 內建完整自訂權限系統（已實作多重資安防護）與完整簽核架構，不必自行開發 | 權限怎麼配、誰該核准什麼、金額門檻定多少 |
| **3 ERP 領域完整性** | 預建台灣公司標準結構的 PostgreSQL，現成產銷人發財模組可一鍵套用並自由修改 | 你新增的計算、交易與併發邏輯 |
| **4 稽核軌跡與法遵** | 完善稽核架構可直接使用，資料讀寫每筆皆可稽核 | 決定哪些業務動作需要留痕 |
| **5 注入與輸入信任** | 外部串接採公司級白名單制，所有對外系統需經公司認可 | 你自己寫的查詢與輸入處理 |
| **6 資料曝光** | 權限系統與公司共表 SOT 化管理，降低資料四散與過度取用 | 你的匯出與報表要開放到什麼程度 |
| **7 秘密與供應鏈** | 免自寫部署腳本、免自管伺服器憑證；AI 生成的變更先在獨立沙盒執行 | 你引入的第三方套件與外部金鑰 |
| **8 基礎設施與維運** | ISO 27001 認證架構、自動備份、統一伺服器資源、視覺化版控、免部署腳本 | 你的營運流程與人員帳號管理 |

開發方式不變：支援 Claude Code 與 Codex 直連，開發成果送入即可預覽上線。
