## 三、必須處理（P0）

每一條用這個格式，**不要用表格**（表格塞不下觸發情境與修法）：

### P0-1　訂單查詢的租戶過濾來自請求參數

**位置**：`src/app/api/orders/route.ts:23`

**會發生什麼**：任何登入的使用者在網址列把 `?company_id=3` 改成 `4`，就會拿到第 4 家公司的完整訂單，包含報價與成本。不需要任何技術能力，也不會留下異常紀錄。

**現況**：
```ts
const companyId = searchParams.get('company_id')
const orders = await db.order.findMany({ where: { companyId } })
```

**怎麼修**：改為從 session 取得租戶識別，並在資料存取層統一處理，而非每支查詢各自處理。同一個模式在 `invoices/route.ts:18`、`reports/route.ts:41` 也存在。

**誰來做**：AI 可代勞（改程式碼）＋ 你要手動（到 Supabase 開啟 RLS 作為第二道防線）
